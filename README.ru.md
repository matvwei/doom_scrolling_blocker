# Doomscroll Blocker

[English](README.md) | **Русский**

Браузерное расширение (Manifest V3 для Chrome и Edge) против doomscrolling: лимиты времени для YouTube, Instagram Reels, TikTok и собственных сайтов. Когда лимит исчерпан — показывает блокирующий экран, перенаправляет или закрывает вкладку.

Без собственного backend: конфигурация и статистика хранятся в `chrome.storage.local`. При открытии popup выполняется запрос к публичному GitHub API для проверки последнего релиза; пользовательские данные не отправляются.

## Возможности

- **Русский и английский интерфейс** — язык переключается в popup или настройках. Выбор сохраняется и применяется к блокирующему экрану, ошибкам валидации и подтверждениям.
- **YouTube** — область ограничения на выбор: «Только Shorts» (`/shorts`, обратная совместимость) или «Весь YouTube» (главная, `/watch`, все страницы). Смена области применяется сразу, без переустановки.
- **Instagram Reels** — лента `/`, `/reels/*`, `/reel/*`; профили, посты и сообщения не трогаются.
- **TikTok** — весь сайт.
- **Пользовательские сайты** — добавляйте свои правила через настройки без JSON: `https://example.com` блокирует домен с поддоменами, `https://example.com/section` — раздел. Для каждого сайта — независимые счётчики и свой набор настроек.
- **Версия и обновления** — popup показывает текущую версию из manifest, независимо запрашивает штатное обновление через `chrome.runtime.requestUpdateCheck()` и сравнивает её с последним опубликованным GitHub Release. Если релиз ещё не опубликован и latest-release API отвечает 404, проверка GitHub просто недоступна; проверка браузера и остальные функции продолжают работать. Если браузер не может автоматически установить доступное обновление, появляется кнопка «Обновить дополнение» со ссылкой на опубликованный релиз. Каждый push в `main` автоматически публикует GitHub Release только после успешного полного CI. Тег — `v<package.json version>`, release notes генерирует GitHub; pull request релиз не создаёт. CI требует stable SemVer, заголовок версии в `CHANGELOG.md` и ещё не занятый удалённый тег: отсутствие bump приводит к отказу, а не к повторному тегу. Только release job получает `contents: write` через `GITHUB_TOKEN`. Для каждого логического изменения обязательны bump версии и changelog entry. Теперь push — публичный выпуск релиза, поэтому перед ним требуется явное согласование. ZIP с GitHub не устанавливается программно: для расширения в режиме разработчика требуется ручное обновление.
- **Немедленные лимиты**: 0 минут означает «блокировать сразу» — действие срабатывает при первом открытии сайта.
- Учёт только активного времени: вкладка активна, окно в фокусе, документ видим.
- Два независимых лимита на цель: сессия (сброс после 10 минут без активности) и день (сброс в локальную полночь).
- Действия: `warning` (блокирующий overlay с вашим текстом и коротким звуковым сигналом), `redirect`, `close`. Сигнал звучит один раз на каждый новый показ предупреждения.
- Пока лимит исчерпан, блокируется каждая вкладка цели — включая новые и при SPA-навигации; после полной перезагрузки overlay показывается заново. При уходе на обычные страницы, росте лимита, отключении или удалении сайта overlay скрывается, а счётчики сохраняются.
- Удаление или изменение overlay через DOM обнаруживается: предупреждение восстанавливается и задаёт вопрос, не снимая ограничение.
- `redirectUrl` не может вести на отслеживаемую зону — защита от бесконечного цикла.
- SPA-навигация обрабатывается корректно.

## Приватность и разрешения

Постоянный доступ к сайтам — только к YouTube, Instagram и TikTok. Отдельно разрешён `https://api.github.com/` для получения номера последней версии; запрос не содержит конфигурацию, статистику или другие пользовательские данные.

Для пользовательских сайтов используются **optional permissions**: доступ к домену запрашивается один раз в момент сохранения настроек и отзывается при удалении сайта. Если доступ не подтверждён — сайт не добавляется и показывается ошибка. Широкий доступ ко всем сайтам (`<all_urls>`) не запрашивается.

Подробная спецификация — [docs/SPEC.md](docs/SPEC.md).

Для ИИ-агентов и контрибьюторов: [AGENTS.md](AGENTS.md) содержит обязательные правила работы и архитектурные инварианты, [docs/AI_CONTEXT.md](docs/AI_CONTEXT.md) — карту модулей и сценарии задач, [.github/copilot-instructions.md](.github/copilot-instructions.md) — правила GitHub Copilot.

## Требования

- Node.js ≥ 22, npm
- Chromium Playwright для локального E2E (`npx playwright install chromium`); CI устанавливает его автоматически

## Установка зависимостей

```bash
npm ci
```

Для локального браузерного E2E отдельно установите тестовый браузер; в Linux запускайте headed-браузер через `xvfb-run -a npm run test:e2e`:

```bash
npx playwright install chromium
# Только Linux, если потребуется: npx playwright install --with-deps chromium
```

Браузер и системные библиотеки остаются тестовыми файлами и не включаются в сборку или архив расширения.

## Ручная установка расширения

Chrome:

1. Откройте `chrome://extensions`.
2. Включите «Режим разработчика».
3. «Загрузить распакованное расширение» → выберите папку `.output/chrome-mv3`.

Edge:

1. Откройте `edge://extensions`.
2. Включите «Режим разработчика».
3. «Загрузить распакованное» → выберите папку `.output/edge-mv3`.

После установки настройте сервисы прямо из popup: кнопка «Настройки» переключает popup на встроенный экран настроек — лимиты, действие, URL перенаправления, текст сообщения, область YouTube, язык интерфейса и пользовательские сайты. Полная страница `options.html` остаётся как fallback: «Расширения → Doomscroll Blocker → Параметры».

## Безопасное внесение изменений и релизы

Штатный путь в `main`: локальные проверки → pull request → успешные обязательные CI checks → необходимый review → merge → проверка post-merge CI и ожидаемого релиза. CI запускается для PR, но workflow сам не обеспечивает защиту ветки. Администратор должен вручную включить и проверить ruleset/branch protection для `main`: обязательные PR и все verify checks, запрет обычного прямого push, force-push и удаления ветки; обход отключён, кроме отдельно согласованной и документированной аварийной процедуры. Релиз публикуется только после успешных проверок при push в `main`; PR релиз не создаёт. Required checks не исключают flaky-тесты, ошибки окружения или регрессию после merge: расследуйте и исправляйте через PR либо используйте проверенный revert/versioned hotfix по ситуации.

## Тесты

```bash
npm test             # юнит-тесты: Vitest + React Testing Library (181 тест)
npm run compile      # typecheck без эмиссии (tsc --noEmit)
npm run build        # production-сборка должна проходить без ошибок
npm run build:edge   # сборка для Edge
xvfb-run -a npm run test:e2e  # E2E в реальном браузере (Playwright; e2e-сборка выполняется автоматически)
```

E2E загружает собранное расширение в Chrome/Edge с временным профилем, перехватывает страницы YouTube и тестового домена локальным HTML, а ответ GitHub Releases API подменяет тестовым релизом — после установки зависимостей и Chromium интернет не нужен. GitHub Actions запускает полный набор тестов/сборок при push в `main` и pull request, а затем публикует релиз только для успешного push в `main`; Chromium устанавливается командой `npx playwright install --with-deps chromium` на эфемерном runner. Файлы Playwright не попадают в сборку или ZIP расширения. Используется GitHub-hosted runner; отдельная Docker-сборка/среда для тестов не нужна.

Геометрия UI проверяется только в реальном браузере (`e2e/geometry.mjs`): каждый видимый интерактивный элемент и текстовый диапазон настроек/popup обязан оставаться внутри своего контейнера и content box окна по горизонтали. jsdom не имеет layout, поэтому этих проверок нет в unit-тестах.

## Структура проекта

```

```

## Ограничения

- Один тик учитывает не более 60 секунд активного времени — после долгого сна устройства возможна недосчитанная минута в пользу пользователя.
- При агрессивной приостановке service worker точность учёта поддерживается будильником и heartbeat content script, но действие блокировки может наступить с задержкой до нескольких секунд. При лимите 0 действие срабатывает сразу при классификации вкладки.
- Лимиты — целые минуты: 0–720 для сессии и 0–1440 для дня.
- Адрес custom-сайта должен использовать стандартный порт (80/443): произвольные порты не выражаются в match-паттернах Chrome.
- Нативный prompt optional permissions недоступен автоматическим кликам, поэтому E2E покрывает путь «доступ предвыдан»; сценарии запроса и отказа покрыты юнит-тестами.
- Нативный prompt закрывает popup: конфигурация сначала сохраняется черновиком (`dsb:pendingConfig`) и достраивается автоматически либо восстанавливается при повторном открытии. Более новое сохранение инвалидирует устаревший черновик, а повреждённый черновик очищается и не применяется.

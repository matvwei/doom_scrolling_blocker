# AGENTS.md — правила работы ИИ с Doomscroll Blocker

Этот файл обязателен для ИИ-агентов, работающих с репозиторием. Детали поведения описаны в `docs/SPEC.md`, актуальная карта проекта — в `docs/AI_CONTEXT.md`. Правила ниже относятся ко всему репозиторию; при появлении вложенных `AGENTS.md` сначала проверяй их область действия.

## 1. Базовые принципы

- Отвечай пользователю на языке его последнего сообщения. Сейчас основной язык общения — русский.
- Перед изменениями изучи затрагиваемые файлы, `git status --short` и связанные тесты. Не перезаписывай и не удаляй чужие незакоммиченные изменения.
- Выполняй запрос целиком: реализация, миграции, локализация, тесты, документация, версия, проверки, коммит и push. Не ограничивайся рекомендацией, если запрошено изменение.
- Сохраняй существующие архитектурные идентификаторы и стиль. Не добавляй зависимости без необходимости; сначала проверь `package.json` и lockfile.
- Не редактируй генерируемые каталоги `.output/`, `.e2e-output/`, `.wxt/`, `node_modules/`. Они обновляются только штатными командами.
- Не читай, не копируй и не передавай секреты, токены, `.env`, приватные ключи и содержимое пользовательского профиля браузера.
- Проект работает в Windows через Git Bash: используй Unix-синтаксис shell и forward slashes в путях.

## 2. Обязательный цикл каждого изменения

Для каждого логически самостоятельного изменения выполни полный цикл:

1. Проверь исходное состояние репозитория и существующие правила.
2. Внеси реализацию и необходимые миграции.
3. Обнови тесты, RU/EN-строки и документацию, если поведение затронуто.
4. Повысь версию приложения (см. §3).
5. Запусти обязательные проверки (см. §8) на итоговом состоянии.
6. Проверь `git status --short`, `git diff --check` и состав коммита; не включай артефакты сборки и чужие файлы.
7. Создай осознанный Conventional Commit с понятной областью изменения.
8. Отправь коммит в `origin main` командой `git push origin main`.
9. Убедись, что push завершился успешно, а рабочее дерево чистое. В ответе укажи версию, hash коммита и результаты проверок.

Не сообщай о завершении при красных тестах, незавершённой реализации или неудачном push. Если внешняя операция заблокирована, явно назови причину и оставшееся действие.

## 3. Версионирование и Git

Версия обязательна после **каждого** изменения, включая документацию:

- новая функциональность, обратно совместимая — minor (`0.4.0` → `0.5.0`);
- исправление, документация, инструкции, рефакторинг без смены API — patch (`0.4.0` → `0.4.1`);
- несовместимое изменение — major; заранее явно опиши миграцию.

Используй:

```bash
npm version <new-version> --no-git-tag-version
```

Команда обновляет `package.json` и `package-lock.json`; сборка WXT переносит версию в manifest. Не редактируй собранный manifest вручную. При изменении версии в тестах и E2E обнови ожидаемую текущую версию и используй более новый mock-релиз для проверки обновления.

- Основная ветка — `main`, remote — `origin`, репозиторий — `https://github.com/matvwei/doom_scrolling_blocker.git`.
- Коммить только относящиеся к задаче файлы; не добавляй чужие изменения без запроса.
- Формат сообщений: `feat: ...`, `fix: ...`, `docs: ...`, `refactor: ...`, `test: ...`, `chore: ...`.
- Push после каждого такого коммита разрешён и обязателен по постоянному правилу пользователя.
- Теги, GitHub Releases, публикацию в магазины и другие публичные релизные действия выполняй только при явном запросе пользователя; обычный commit+push не создаёт релиз автоматически.
- Не делай force push, reset/rebase опубликованной истории или удаление веток без отдельного явного запроса.

## 4. Архитектурные границы

- `core/` — чистая доменная логика без Chrome API: matching, custom rules, limits, config/migrations, i18n, update version logic, warning sound.
- `adapters/` — Chrome API: storage, permissions, dynamic content scripts, pending draft resume, browser update check.
- `entrypoints/background.ts` — оркестрация вкладок, учёта, enforcement, регистрации скриптов и обновлений; конечный автомат лимитов остаётся в `core/limits.ts`.
- `entrypoints/content.ts` — heartbeat, SPA-сигналы, Shadow DOM overlay, звук и защита overlay от DOM-вмешательства.
- `components/`, `entrypoints/popup/`, `entrypoints/options/`, `hooks/` — React UI и доступ к данным через адаптеры; не дублируй бизнес-логику.
- `tests/` — Vitest + React Testing Library; `e2e/` — Playwright с реальным браузером и локальными/mocked ответами.

## 5. Инварианты, которые нельзя нарушать

### Лимиты и состояние

- `0` минут — немедленная блокировка при входе, а не «без лимита».
- Сессия: 0–720 целых минут, сброс после 10 минут неактивности. День: 0–1440, сброс в локальную полночь.
- Время засчитывается только для активной вкладки, сфокусированного окна и видимого сфокусированного документа; несколько вкладок одной цели не умножают скорость учёта.
- `enabled=false` немедленно снимает enforcement/overlay, но сохраняет счётчики.
- `blockedReason` имеет приоритет `session` над `daily`; latch не должен дёргаться между тиками.
- На полной загрузке (`tabs.onUpdated`, `status='loading'`) сбрасываются per-tab `overlayShown` и `actionTaken`, чтобы блокировка появилась в новом DOM. SPA-навигация не равна полной загрузке.
- Счётчики переживают service worker/browser restart; записи сериализуются через очередь storage adapter.

### URL и redirect

- Custom-правила проверяются раньше built-in; при равном домене побеждает первое в списке.
- Схема учитывается строго; path prefix имеет границу компонента (`/foo` не совпадает с `/foobar`).
- Custom URL допускает только HTTP(S), стандартные порты и отсутствие credentials; query/hash отбрасываются.
- Redirect никогда не должен вести в любую отслеживаемую зону текущей конфигурации; UI валидирует это, background имеет runtime fallback в warning.

### Overlay

- Overlay изолирован Shadow DOM, не даёт продолжить просмотр и не дублируется при повторных сообщениях.
- Звук играет один раз на новый показ, не на каждое обновление; ошибка autoplay не ломает overlay.
- `MutationObserver` восстанавливает удалённый/изменённый host, атрибуты или Shadow DOM и показывает локализованный tamper-вопрос. Ответ не снимает ограничение.
- Штатные `show()`/`hide()` не должны считаться tamper-событием.

### Permissions и приватность

- Обязательный `<all_urls>` запрещён. Built-in hosts и `https://api.github.com/*` перечислены явно.
- Custom-сайты получают минимальный optional origin только после нативного разрешения; отказ означает, что сайт и настройки не сохраняются.
- При удалении/редактировании сайтов динамические регистрации, usage и неиспользуемые origins приводятся в соответствие конфигурации.
- Не добавляй backend или отправку пользовательских данных. Единственный внешний запрос сейчас — публичный GitHub Releases API при открытии popup.

### Pending configuration

- Нативный permission prompt может закрыть popup: до запроса сохраняется `dsb:pendingConfig`.
- Любое новое сохранение `dsb:config` инвалидирует stale draft.
- Resume перечитывает draft перед записью; повреждённый draft только очищается, без нормализации и молчаливого применения defaults.

## 6. Мультиязычность

- Поддерживаются `ru` и `en`; default и миграция старых конфигов — `ru`.
- Любую новую системную строку добавляй в оба словаря `core/i18n.ts`. `Record<MessageKey, string>` должен гарантировать компиляционную проверку полноты английского словаря.
- Используй `translate(language, key, params)`; не добавляй новые hardcoded UI-строки в React/background/content.
- Переключатель языка сохраняет только `config.language`, не сохраняя остальные несохранённые поля формы.
- Background передаёт язык через `OverlayMessage`; validation errors выбираются по языку проверяемого конфига.
- Пользовательские сообщения и имена сайтов не переводятся автоматически.
- Для UI-изменений проверяй обе локали и геометрию; тесты обновлений и валидации также не должны зависеть от случайной локали.

## 7. Документация

- `README.md` — основной английский README.
- `README.ru.md` — русский README; пользовательские возможности и команды держи синхронизированными с английским.
- `docs/SPEC.md` — нормативная подробная спецификация поведения, хранения, разрешений, UI и тестирования.
- `docs/AI_CONTEXT.md` — практический контекст и карта модулей для ИИ.
- `.github/copilot-instructions.md` — краткие Copilot-правила, не заменяет этот файл.
- При изменении поведения обнови SPEC и соответствующие README; при изменении архитектуры/рабочего процесса обнови также AI-файлы.
- Счётчики тестов в документации обновляй по фактическому успешному прогону.

## 8. Проверки

Для изменений кода обязательны:

```bash
npm test
npm run compile
npm run build
npm run build:edge
npm run test:e2e
```

Можно начать с focused tests, но финальный прогон должен быть полным. Для изменений только документации допустимы проверка ссылок/диффов, `npm run compile`, `npm run build`, `npm run build:edge`; полный unit/E2E запускай, если затронуты ожидаемые версии, fixtures или тестовые сценарии.

E2E должен оставаться автономным: YouTube/custom hosts и GitHub API перехватываются, реальный интернет не требуется. Нативный permission prompt не автоматизируется кликом; request/denial покрываются unit/component tests, а E2E использует предвыданный origin.

После проверок удали только созданные тобой ненужные логи/артефакты; существующие чужие файлы не трогай. Не фиксируй `.output/` и `.e2e-output/`.

## 9. Частые задачи

- **Новый built-in/custom URL:** изменить matching + permissions/manifest + registrations + тесты + SPEC/README.
- **Новое поле конфигурации:** тип + defaults + normalize/migration + form conversion + validation + pending compatibility + RU/EN + тесты.
- **Новое UI-поле:** popup/options оба режима + RU/EN + ошибки + geometry E2E.
- **Новое действие блокировки:** тип + validation + background + content/message contract + multi-tab/reload + RU/EN + unit/E2E.
- **Изменение версии/update flow:** `core/updates.ts`, `adapters/updates.ts`, `hooks/useUpdates.ts`, popup, fake Chrome и E2E mock; GitHub ZIP нельзя представлять как автоустановку.
- **Изменение правил для ИИ:** синхронно проверить `AGENTS.md`, `.github/copilot-instructions.md`, `docs/AI_CONTEXT.md` и §11 SPEC.
